# 국군복지단 가격조사 도우미 프로젝트 상태

최종 갱신: 2026-07-06
상태: 현장 사용 초안 + 기능 확장 진행 중
배포: GitHub Pages / PWA
저장 방식: 서버 DB 없음, 브라우저 IndexedDB 저장

이 문서는 현재 앱의 구현 상태, 데이터 구조, 주요 기능, 운영상 주의사항을 한곳에 모아두는 기준 문서다. 기능을 추가하거나 업무 규칙이 바뀌면 이 문서도 함께 갱신한다.

## 1. 프로젝트 목적

이 앱은 국군복지단 가격조사 현장 업무를 모바일, 태블릿, PC에서 빠르게 수행하기 위한 오프라인 우선 PWA다.

기존 방식은 조사표 엑셀을 현장에서 직접 찾고, 사진을 따로 촬영한 뒤, 나중에 파일명을 맞추는 흐름이었다. 현재 앱은 사용자가 조사표, 연락처, 바코드 이미지 엑셀을 업로드하면 브라우저 내부에 지역, 매장, 물품 작업환경을 만들고, 현장에서 가격, 진열 여부, 사진, 특이사항을 바로 입력한 뒤 지역별 엑셀, 사진 ZIP, 백업 JSON을 내보낼 수 있게 한다.

## 2. 현재 데이터 운용 방식

기본 자료는 앱 코드에 고정하지 않는다. 사용자가 직접 업로드한 엑셀 파일을 기준으로 브라우저 저장공간에 작업 데이터가 생성된다.

필수 업로드 파일:

- 조사표 엑셀
- 업체 연락처 엑셀
- 바코드 이미지 엑셀

저장 원칙:

- 입력 자료와 현장 조사 데이터는 서버가 아니라 해당 기기의 해당 브라우저 IndexedDB에 저장된다.
- 같은 휴대폰이라도 브라우저가 다르면 데이터가 공유되지 않는다.
- 다른 기기에서 이어서 작업하려면 전체 백업 JSON을 내려받아 새 기기에서 복원해야 한다.
- 앱을 새 링크나 새 리포지토리 경로로 배포하면 브라우저 저장공간도 별도로 분리된다.

## 3. 기술 스택

- React
- Vite
- TypeScript
- PWA
- IndexedDB
- SheetJS/xlsx
- JSZip
- Leaflet / OpenStreetMap
- lucide-react
- GitHub Pages

서버 DB, 서버 API는 사용하지 않는다. 지도 타일과 주소 검색, 현재 위치 확인처럼 인터넷이 필요한 일부 기능을 제외하면 현장 입력은 오프라인 사용을 목표로 한다.

## 4. IndexedDB 구조

주요 object store:

- `surveyFiles`: 업로드 원본 파일 메타데이터
- `regions`: 지역 목록과 담당부서, 집계 캐시
- `stores`: 매장 단위 정보
- `items`: 물품 단위 조사 정보
- `photos`: 매장/물품 사진 Blob
- `settings`: 현재 지역, 최근 화면, 담당매장 설정 등

주요 데이터 단위:

- 지역: 조사표의 지역 기준
- 매장: 방문 조사 대상 단위
- 물품: 가격조사 입력 단위
- 사진: 매장 전경, 제품진열, 제품정보, POS/영수증

모든 주요 데이터는 `region`과 `storeId`를 기준으로 분리된다.

## 5. 화면 구조

현재 주요 화면:

- 자료 업로드
- 메인
- 담당매장 관리
- 매장리스트
- 매장지도
- 매장정보
- 물품리스트
- 가격정보
- 검증
- 백업/복원

상단 바는 현재 화면의 이름만 간결하게 표시한다. 지역, 매장 같은 현재 작업 컨텍스트는 메뉴와 화면 내부 정보로 확인하는 방향이다.

브라우저/휴대폰 뒤로가기:

- 내부 화면 이동은 브라우저 히스토리에 맞춰 동작한다.
- 메인 또는 업로드 화면에서 뒤로가기를 누르면 바로 종료되지 않도록 한 번 더 누르면 종료된다는 토스트를 표시하는 구조가 적용되어 있다.
- 일부 모바일 브라우저는 홈 화면 바로가기/PWA 모드에서 뒤로가기 동작이 브라우저 정책 영향을 받을 수 있다.

## 6. 자료 업로드와 파싱

조사표:

- 지역, 매장, 물품 목록을 만든다.
- 조사표 안의 주소는 매장 주소와 상세주소 성격이 섞여 있을 수 있어, 최신 양식에서는 `최종주소`를 매장 위치 검색과 지도 기준 주소로 사용한다.
- 기존 주소 열은 가격정보 화면의 국군복지단 제시정보에서 `상세주소`로 참고 표시한다.

업체 연락처:

- 매장/물품별 담당자명과 연락처를 연결한다.
- 앱 화면에서는 “담당자 정보”로 표현한다.
- 제조사는 물품에 속한 정보이며, 담당자 연락처 영역에는 표시하지 않는 방향으로 정리했다.

바코드 이미지:

- 바코드 이미지 엑셀에서 물품코드가 있는 행의 바코드 이미지를 그대로 매핑한다.
- 이미지를 분석해서 바코드 숫자를 다시 읽는 방식이 아니라, 같은 행의 물품코드와 이미지 위치를 기준으로 연결한다.
- 물품리스트의 바코드/POS 모달에서 해당 물품의 바코드 이미지를 보여준다.

## 7. 메인

메인은 지역별 전체 진행 상황을 보는 화면이다.

지역 카드 표시:

- 지역명
- 상세지역
- 담당부서
- 전체 매장/물품 진행률
- 담당매장을 설정한 경우 담당 매장/담당 물품 진행률
- 작업, 엑셀, 사진, 백업 버튼
- 담당매장 관리 메뉴

담당매장 기본값은 전체 선택이 아니라 전체 미선택이다. 담당매장을 따로 지정하지 않으면 담당 기준 진행률은 0/0으로 표시된다.

## 8. 담당매장 관리

담당매장 관리는 한 지역 안에서 내가 맡은 매장만 추려서 작업하기 위한 기능이다.

기능:

- 매장 체크/해제
- 전체 선택/전체 해제
- 담당매장 수 표시
- 위치 없는 매장 수 표시
- 없는 위치만 가져오기
- 전체 위치 가져오기

주소 검색은 인터넷이 필요하다. 주소는 우편번호나 매대 설명을 제거하고, 실제 위치 검색에 적합한 최종주소를 우선 사용한다.

위치 정보는 브라우저에 저장되므로 한 번 가져온 매장은 다음부터 다시 검색하지 않아도 된다. 다만 주소가 바뀌었거나 잘못 잡혔으면 전체 위치 가져오기로 갱신할 수 있다.

## 9. 매장리스트

매장리스트는 실제 방문 순서와 작업 대상을 고르는 화면이다.

검색 대상:

- 매장명
- 주소
- 물품명
- 물품코드
- 바코드
- 담당자

필터:

- 전체
- 미완료
- 완료
- 사진누락

정렬:

- 이름순
- 품목 많은 순
- 미완료 많은 순
- 거리순

거리순은 현재 위치와 매장 좌표가 있을 때 사용할 수 있다. 내 위치 버튼을 누르면 현재 위치를 갱신하고, 거리 표시와 거리순 정렬에 반영한다.

매장 카드:

- 매장명
- 영업 상태
- 주소
- 물품 완료 수 / 전체 수
- 진행률 바
- 현재 위치로부터 거리
- 사진 누락 건수
- 조사일
- 담당자 정보
- 입력
- 3점 메뉴

완료된 매장은 카드 스타일로 완료 상태가 더 잘 드러나도록 처리한다.

## 10. 매장지도

매장지도는 담당매장을 지도에서 확인하고 방문 순서를 잡기 위한 화면이다.

기능:

- Leaflet / OpenStreetMap 기반 지도 표시
- 현재 위치 표시
- 담당매장 마커 표시
- 완료/미완료 상태를 마커 색상으로 구분
- 마커 선택 시 하단 매장 카드 변경
- 매장 카드에서 담당자 정보, 입력, 3점 메뉴 사용

동작 원칙:

- 매장지도 진입 시에는 기본적으로 현재 위치 기준으로 본다.
- 매장리스트의 3점 메뉴에서 `매장지도에서 보기`를 선택하면 해당 매장을 중심으로 지도와 카드가 열린다.
- 내 위치 버튼을 누르면 선택 매장을 해제하고 현재 위치 중심으로 이동한다.
- 마커를 누르면 지도 확대가 강제로 바뀌지 않고, 선택 카드만 해당 매장으로 바뀐다.

지도 타일은 인터넷 연결과 OpenStreetMap 타일 응답 상태의 영향을 받는다.

## 11. 매장정보

매장정보 화면은 방문 매장 단위의 기본 입력 화면이다.

입력/표시 항목:

- 매장명
- 주소
- 매장 전경사진
- 현재 상태
- 방문 조사일
- 담당자 정보
- 조사 입력 버튼

매장 전경사진:

- 촬영
- 선택
- 기존 전경사진 사용

기존 전경사진 사용은 앱에 이미 저장된 매장 전경사진을 골라 현재 매장에 복제하는 기능이다. 같은 장소가 조사표에서 별도 매장처럼 잡힌 경우 사진을 다시 찍지 않고 재사용할 수 있다.

매장 상태:

- 미확인
- 영업 중
- 폐업
- 임시휴업

매장 상태 변경 규칙:

- 전경사진이 없는 매장은 기본적으로 미확인이다.
- 전경사진을 입력한 뒤 상태를 설정한다.
- 영업 중이 아닌 매장은 물품 가격정보 저장이 제한된다.
- 폐업/임시휴업 처리 시 하위 물품에 일괄 상태가 반영된다.
- 폐업/임시휴업에서 영업 중으로 되돌리면 기존 자동 입력값을 정리하고 다시 조사할 수 있도록 한다.

## 12. 물품리스트

물품리스트는 매장 안의 물품을 선택하는 화면이다.

검색 대상:

- 물품명
- 바코드
- 물품코드
- 담당자

표시 정보:

- 물품코드
- 물품명
- 완료/미조사 상태
- 사진누락 뱃지
- 바코드
- 기준가격
- 조사가격
- 적격/부적격
- 사진 미리보기
- 입력 버튼
- 바코드 버튼

사진누락은 완료된 물품 중 필요한 사진 조합이 부족한 경우 표시한다.

미진열 필터:

- 미진열 물품만 모아 POS 확인을 진행할 수 있도록 필터 기준을 추가했다.

## 13. 바코드 / POS 확인 모달

바코드 버튼을 누르면 물품의 바코드 이미지를 크게 보여준다.

목적:

- 미진열 상품을 계산대/POS에서 연속 확인할 때 사용
- 물품리스트에서 바로 바코드를 보여주고 다음 물품으로 넘기며 확인 가능

구성:

- 현재 순서 / 전체 수
- 물품코드와 물품명
- 바코드 숫자
- 바코드 이미지
- 입력 버튼
- 이전 / 다음 버튼

입력 버튼을 누르면 가격정보 화면으로 이동하며, 상태/POS 입력 위치로 바로 내려가도록 구성되어 있다. 바코드 모달에서 들어온 물품은 저장 후 다시 바코드 모달 흐름으로 돌아갈 수 있도록 설계되어 있다.

## 14. 가격정보

가격정보는 물품별 조사 내용을 입력하는 핵심 화면이다.

구성:

- 상단 물품 요약
- 담당자 정보
- 국군복지단 제시정보
- 실물 확인
- 상태
- 사진자료
- 가격
- 특이사항
- 하단 고정 저장 바

담당자 정보:

- 담당자명
- 연락처
- 연락처는 누르면 바로 전화 연결

국군복지단 제시정보:

- 물품코드
- 제조사
- 물품명
- 규격
- 기준가격
- 바코드
- 상세주소

실물 확인:

- 진열여부 O/X
- 규격일치 O/X
- 바코드일치 O/X

진열여부가 X이면 규격일치와 바코드일치는 입력하지 않고, 상태 입력 영역을 사용한다.

상태:

- 바코드 등록 여부 O/X
- 판매여부: 미진열 / 미판매
- POS 조회 여부: 조회함 / 조회불가

POS 조회 여부는 비고 문구와 연동된다. 조회함이면 POS 조회 관련 문구를 추가하고, 조회불가로 바꾸면 조회불가 문구로 정리한다.

사진자료:

- 제품진열사진
- 제품정보사진
- POS/영수증사진

제품정보사진은 바코드 자동 인식을 시도한다. 인식 결과가 조사표 바코드와 다르면 바코드 불일치 판단에 활용한다.

제품진열사진과 POS/영수증사진은 가격 OCR 후보 추출을 시도한다. 인식된 가격 후보는 정상가/할인가 입력 근처에 칩으로 표시하고, 사용자가 눌러 입력할 수 있다.

사진은 저장 전에 리사이징/압축해 브라우저 저장공간 부담을 줄인다.

가격:

- 기준가격 참고 표시
- 정상가
- 할인 여부
- 행사 여부
- 할인가
- 할인기간: 상시할인 / 기간할인 / 모름
- 구두 확인
- 시작일 / 종료일
- 기간 구분: ① 31일 이내 / ② 32일 이상

가격 입력 시:

- 천 단위 콤마를 표시한다.
- 기준가격과 조사가격을 비교해 정상/주의 문구를 표시한다.
- 기준가격 대비 차이가 크면 별도 주의 문구를 표시한다.

특이사항:

- 비정상진열 O/X
- 비고 직접 입력
- 문구 칩 토글

문구 칩:

- 폐점
- 품절
- 재고 소진
- 재입고 예정
- 1+1 행사
- 임시휴업
- 판매처 미협조
- 가격 수기 입력

칩으로 추가한 문구는 다시 누르면 제거된다. 사용자가 직접 입력한 문구는 가능한 건드리지 않는 방향으로 처리한다.

저장:

- 가격정보 화면에서는 저장 버튼을 눌러야 DB에 반영된다.
- 화면 이동 전 수정값이 있으면 저장하지 않고 나갈지 확인한다.
- 저장 후 다음 미등록 물품으로 이동하거나, 전 물품 완료 시 매장리스트로 돌아갈지 선택할 수 있다.

## 15. 적격/부적격 판단

앱은 조사 결과를 기준으로 적격/부적격을 자동 표시한다.

주요 판단 기준:

- 정상 판매 및 정상 가격: 적격
- 업체 제출 가격보다 조사 가격이 낮은 경우: 부적격 위험
- 미판매
- 미진열
- 바코드 미등록
- 폐점/임시휴업
- 장기 할인
- 1+1 행사 가격 환산

판단 결과는 물품리스트에 뱃지로 표시하고, 조사자가 빠르게 확인할 수 있게 한다.

## 16. 사진 규칙과 ZIP 내보내기

사진 저장:

- 매장 전경사진은 매장당 1장 저장한다.
- 제품진열사진, 제품정보사진, POS/영수증사진은 물품별로 저장한다.

사진 ZIP 파일명:

- `물품코드.1.jpg`: 매장 전경사진
- `물품코드.2.jpg`: 제품진열사진
- `물품코드.3.jpg`: 제품정보사진
- `물품코드.4.jpg`: POS/영수증사진

매장 전경사진은 실제 저장은 매장당 1장이지만, ZIP 생성 시 각 물품코드의 `.1.jpg`로 복제해 넣는다.

## 17. 엑셀 내보내기

지역별 엑셀 내보내기를 지원한다.

내보내기 원칙:

- 조사표 양식과 유사한 컬럼 순서로 생성한다.
- 원본 기준정보와 현장 입력값을 함께 포함한다.
- 저장된 조사일이 없는 미조사 물품에는 조사일을 넣지 않는다.
- 기간구분과 바코드 등록 여부 사이에 가격판단 열을 포함한다.

가격판단:

- 기준가격과 조사가격이 같으면 동일
- 조사가격이 기준가격보다 높으면 고가
- 조사가격이 기준가격보다 낮으면 저가

## 18. 백업/복원

백업 종류:

- 지역 백업
- 전체 백업

전체 백업에는 다음이 포함되어야 한다.

- 업로드 파일 기반으로 생성된 지역/매장/물품 목록
- 담당매장 설정
- 위치 정보
- 입력값
- 사진 Blob
- 바코드 이미지 매핑
- 앱 설정

다른 기기로 작업을 옮길 때는 전체 백업을 내려받아 새 기기에서 복원한다.

## 19. 저장공간

앱 메뉴에서 저장공간 상태를 확인할 수 있다.

표시 항목:

- 저장 사진 수
- 사용 중 용량
- 여유 공간

브라우저 저장 가능 용량은 기기, 브라우저, 남은 저장공간, 브라우저 정책에 따라 달라진다. 많은 사진을 저장하는 현장 업무 특성상 지역별 또는 일자별 전체 백업을 자주 내려받는 것이 안전하다.

## 20. 오프라인 사용 범위

오프라인 가능:

- 지역/매장/물품 목록 조회
- 매장정보 입력
- 가격정보 입력
- 사진 촬영/첨부
- 임시/완료 저장
- 검증
- 백업 JSON 내보내기

인터넷 필요:

- GitHub Pages 최초 접속 또는 새 버전 로드
- 지도 타일 표시
- 주소 기반 위치 가져오기
- 현재 위치 권한 확인
- 외부 지도 링크 열기

## 22. 남은 과제와 리스크

- OCR 가격 인식 정확도는 촬영 환경과 가격표 형태에 따라 편차가 크다.
- 바코드 자동 인식은 브라우저 지원 여부와 사진 품질 영향을 받는다.
- OpenStreetMap 지도 타일은 외부 서비스 상태와 네트워크 영향을 받는다.
- 주소 검색은 무료 검색 기반이라 매장 주소 품질에 따라 좌표가 부정확할 수 있다.
- 모바일 브라우저의 파일 선택, PWA 뒤로가기, 저장공간 정책은 기기별 차이가 있다.
- 사진 수가 매우 많아지면 백업/복원과 ZIP 생성 시간이 길어질 수 있다.

## 23. 운영 권장사항

- 조사 전 같은 기기와 같은 브라우저를 계속 사용할지 확정한다.
- 현장 투입 전 조사표, 연락처, 바코드 이미지 엑셀을 업로드하고 지역/매장 수를 확인한다.
- 담당매장을 미리 지정하고, 필요한 경우 전체 위치 가져오기를 먼저 실행한다.
- 매일 조사 종료 후 전체 백업을 내려받는다.
- 지역 완료 후 지역 엑셀과 사진 ZIP을 내려받아 별도 보관한다.
- 앱 업데이트 후 이상이 있으면 새로고침 또는 캐시 초기화 후 재접속한다.
